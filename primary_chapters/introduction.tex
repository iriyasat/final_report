\chapter{Introduction}

\section{Overview / Background of the Work}

Managing multi-branch automotive dealerships presents significant software engineering challenges. Dealership groups operate across multiple physical stores, requiring real-time inventory management, role-restricted employee access, automated sales invoicing, and executive financial reporting. Legacy dealership systems frequently rely on fragmented desktop software or manual spreadsheet logs, introducing data redundancy, slow communication between customer inquiries and store staff, and delayed reporting.

This project was developed during a 3-month undergraduate internship at \textbf{Radiant Pharmaceuticals Limited} (ICT Wing, MIS) from May 17, 2026, to August 16, 2026, focusing on the engineering of an integrated automotive management platform to address these operational bottlenecks. The software unifies a back-office enterprise ERP engine (\texttt{car\_sales}) and a customer-facing e-commerce storefront (\texttt{ecommerce}) within a single Django framework instance.

\section{Objectives}

The primary objective of this project is to construct a unified automotive software platform that connects internal dealership enterprise resource planning (ERP) with customer-facing e-commerce features and executive analytical reporting tools. Specifically, the project aims to:
\begin{enumerate}
    \item Build a multi-branch dealership portal (\texttt{car\_sales}) featuring a 9-tier role-based access control (RBAC) security matrix to scope data visibility across executives, store managers, and sales representatives.
    \item Implement a custom authentication backend (\texttt{EmployeeBackend}) enabling staff to log in using numeric IDs while automatically detecting role scopes.
    \item Design a raw SQL star-schema analytical engine to calculate store sales summaries, budget variances, and customer spending metrics with sub-20ms execution latency.
    \item Develop a customer-facing web storefront (\texttt{ecommerce}) offering vehicle catalog filtering, side-by-side spec comparison for up to 4 vehicles, wishlist management, test-drive scheduling, and atomic cart checkouts.
    \item Expose clean REST API endpoints (\texttt{/api/}\allowbreak\texttt{vehicles/}, \texttt{/api/}\allowbreak\texttt{sales/}, \texttt{/api/}\allowbreak\texttt{stores/}, \texttt{/api/}\allowbreak\texttt{emproles/}) and verify system stability using an automated test suite.
\end{enumerate}

\section{Scopes}

The project scope is structured across five core software engineering domains:
\begin{itemize}
    \item \textbf{Backend Engineering:} Relational database modeling, business logic implementation, transaction management, and REST API development.
    \item \textbf{Database Optimization:} Star-schema dimensional modeling, database indexing, and raw SQL aggregation routines.
    \item \textbf{Security Engineering:} 9-tier RBAC permission hierarchy, numeric ID authentication, and PBKDF2 password hashing.
    \item \textbf{Frontend Design:} Responsive HTML5, Bootstrap 5, and Vanilla CSS templates with lightweight AJAX interactivity.
    \item \textbf{Quality Assurance:} Automated test suite execution, data export generation (JSON/CSV), and performance benchmarking.
\end{itemize}
